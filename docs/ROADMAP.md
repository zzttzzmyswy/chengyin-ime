# 长期路线图

## 目标与已确定方向

用户已确定：全拼优先、随后双拼。最初优先 Linux 桌面；2026-10-03 因用户当前方便使用 Windows，调整为优先交付 Windows 桌面试用版。所有阶段都保持 Windows、Linux X11、Linux Wayland、Android 共享解码核心的边界。

“极致性能”转化为可复现的延迟、内存、分配次数、启动速度和移动端能耗指标；“兼容性”转化为按系统、协议、应用和输入场景逐项记录的测试。不能只凭一次基准、成功编译或框架支持列表宣布达标。

首期选择：Rust 核心 + C ABI + C++ Fcitx 5 适配。选择理由是共享安全的词典和会话逻辑、控制内存分配，同时复用桌面输入法基础设施。Windows 使用 TSF，Android 使用 Kotlin InputMethodService + JNI/NDK。C++ 限于原生平台接口。暂不维护独立 Wayland 输入法服务或全局键盘钩子。

## 里程碑

按验收结果推进，不用未经验证的工期承诺代替进度。每次迭代完成一个可运行切片，更新 STATUS 并保存测试证据。用户测试机会有限：开发切片先内部验证，达到较完整的功能门槛后集中实测；Windows 使用单个离线安装 EXE。

## M2 解码与数据决策

- 先建立带来源与许可证清单的词库候选集合，分开代码许可、词库许可和语料使用条件。演示词表不能用于宣称输入准确率。
- 整句解码：全拼规范化 → 音节 DAG（保留多种切分）→ 词典边 → 有界 beam/Viterbi → top-k 候选。先实现可解释的 unigram/bigram 基线；只有真实评测改善才引入更复杂模型。
- 将按键编辑区间与解码缓存关联，退格或中间编辑只失效受影响部分；给 beam 大小、输入长度和候选页设置显式预算。
- 词典编译为版本化二进制，校验头、偏移、长度、UTF-8、排序与校验和；同一语料对比当前 trie、压缩 trie、FST/双数组，再选择有实测收益的布局。
- 当前 top-9 缓存适合原型首屏，不适合完整翻页。M2 使用可继续遍历的候选游标/解码结果，不靠扩大固定数组解决问题。

## 优先级原则

丢字/重上屏/输入串跨窗口/宿主崩溃 > 协议和焦点正确性 > 日常词句覆盖 > 性能优化 > 外观和附加功能。保留离线基本功能；云候选、同步、生成式补全、语音和花哨皮肤不进入前几个里程碑。

每个平台采用原生 UI；核心不依赖 GUI、显示服务、文件路径或网络。先建立准确的参考实现与回归集，再优化热点。只在瓶颈证据明确时采用 SIMD、无锁结构、mmap 等措施。
