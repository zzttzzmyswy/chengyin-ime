## 本批修复的缺陷

### R01 · P1 · 清空一个学习文件会丢弃另一文件的待保存事件

位置：`platforms/windows/preferences.cpp` 的 `updateProfile/importProfile/clearProfile`，
`learning_writer.cpp` 构造器和 `service.cpp` 的学习代际读取。
原来所有路径共用 `Local\\MyswyIME.LearningGeneration`。清空 A 增加代际后，
B 已排队事件的 expectedEpoch 也会过期，写入函数将其当作被用户清空的事件并返回成功的 no-op。
测试临时文件也能影响真实文件的待保存队列。

修复：代际映射绑定规范绝对路径的 SHA-256，统一大小写与分隔符；所有读取/写入/清空/导入
使用同一函数。映射名称生成失败则明确拒绝需要代际保护的操作，不能退回全局学习代际。
不修改 profile 文件格式、容量或学习内容，也不在按键路径计算文件摘要。

验证：原生 `windows_settings_test` 在主线程持有磁盘锁时，为两个临时文件排队，清空其中一个，
解锁并排空线程；清空的事件失效，另一个事件仍持久化。另检查大小写/斜杠别名、不同文件和旧事件
不能复活被清空的数据。测试使用独立文件；没有为了复现旧缺陷去增加真实用户的旧全局代际。

### R02 · P2 · 显式分隔的组合声母被改读为更多字的缩写

位置：`crates/ime-core/src/dictionary.rs::initials_range`。
`zh'r'm` 原来删除撇号后按 `zhrm` 查四字索引，四字“走火入魔”会遮住明确的三音节解释。
基线回归实际输出四字，违反用户明确分段意图。

修复：只将未分隔的逐字首字母或 `s's'd'd` 这样的单字母分段交给严格同字数索引；
`zh/ch/sh` 显式音节头交给原匹配流程。`zhrm` 仍优先四字词。
验证：基线失败/修复通过的同一 fixture，另保留生产 `ssdd/zgrm/zhrm`、分页及规则组合回归。

### R03 · P2 · 词库未分隔拼音的贪心解析漏掉有效字数

位置：`Dictionary::build_initials`。
旧实现按最长音节切分，再检查字数；例如自造测试条目 `baban` 可切为 `ba'ban` 两音节，
也可切为 `ba'ba'n` 三音节。三字条目直接被索引遗漏，`bbn` 无候选。
这里使用鼻音和自造文字只验证索引，并非新增生产词条。

修复：带完整分隔符的常规词条走快速路径；其余在初始化阶段按“字数＋拼音位置”做有界 DP，
选取符合字数的完整合法音节路径。沿用 255-byte 规范词条上限，不错误套用 63-byte 输入上限。
不增加按键分配，不改变磁盘词库格式。TSV 与二进制重新加载均有回归。

限制：没有分隔符且存在多个相同字数的合法读音时，拼音字符本身不足以确定真实读音，当前仍
只选择一个确定路径。不能声称该 DP 解决全部音节歧义；数据规范化与多解析范围见 R12。

### R04 · P2 · 末尾分隔符使整词候选消失，学习键也不能保存

位置：`CandidateCursor::reset/reset_fast`、`Session::after_commit`。
当 `ni'hao` 是叶端词条时，输入 `nihao'` 后 cursor 尝试继续走不存在的分隔边，整词消失。
即使其他通道给出整词，末尾撇号进入 learning_key 也会被学习格式校验拒绝。

修复：尾部分隔只在不存在真实下一音节边、且节点是完整 terminal 时由终端吸收；真实
`ni' -> ni'hao` 继续完成行为保留，未完成音节不能靠这条规则成为整词。
完整提交的学习键去掉末尾分隔，原始 preedit/输入跨度不提前改动。

验证：关闭/全开模糊规则，候选 consumed 包含 6 bytes，选择仅上屏“你好”、剩余为空，学习一次
并可二进制重载；既有显式边界测试继续通过。实现时曾用一律 trim 的方案，被 `ni'` 回归拦住，
已改为上述终端规则，未调整旧测试期望掩盖语义退化。

### R05 · P2 · 更新器接受版本标签、包名和下载地址不一致的资源

位置：`platforms/windows/update.cpp::parseReleases/validAsset/verifyReleaseImage`。
原来只验证名称前后缀和仓库 URL 前缀，未来版本的 release 可夹带旧版本名称/地址，
界面宣称的更新版本与下载对象不一致。摘要仍可匹配那个旧文件，不能靠 SHA-256 修正版本绑定。
`draft` 的字符串值 `"false"` 也不应被当作 JSON 布尔值。

修复：标签、由标签生成的唯一 MSVC x64 文件名和完整仓库 release URL 三者一致；
严格检查 draft/tag/assets/name/url/digest 字段类型。下载后的 image 校验复用绑定规则，
保持摘要、大小和 x64 PE/非 DLL 验证。

验证：基线包名错配测试失败；修复后的原生测试覆盖包名错配、URL 标签错配、非布尔 draft、
image 版本错配，并保留正确 Unicode note、旧版拒绝、外部地址、坏 JSON 和篡改内容检查。
没有发布真实 Release 或下载/执行远端更新包。

### R06 · P3 · 严格首字母索引没有覆盖 a/e/o 零声母音节

位置：`Dictionary::initials_range`。
旧索引虽然生成 `ai -> a` 的 key，查询入口却只接受辅音；此类输入只能依赖旧有界搜索。
小词库的回归在旧版本也可能通过，因此这是覆盖一致性改进，不把它写成每次都无候选的复现缺陷。

修复：接受 a/e/o 首字母，如 `aqdy`；完整可解析全拼继续使用原流程，`nihao` 不改读成更多字的缩写。
验证：稀有规范词条、全规则/关闭规则和全拼保留；零分配用例补充 `aqdy/zh'r'm/nihao'`。

## 其他调用链问题与测试隔离

### R07 · P1 · 普通学习更新未同步其他已激活服务的 profile

证据：`preferences.cpp::updateProfile` 成功保存只返回；`configuration.cpp` 检测配置代际和
preferences 文件；`service.cpp::receiveConfiguration` 仅在清空/导入学习代际不同或重新启用
学习时设置 replaceProfile。应用 A 的普通选择不会让应用 B 的既有 profile 得到更新。

这项是持久文件可正确合并、内存快照却缺少普通更新通道的问题，与已修复的设置外观同步不同。
当前有调用链证据，尚未完成两个真实生产宿主的复现。下一批引入独立、非破坏性的学习 revision，
在后台获取新快照，活动 composition 结束后再应用；清空 generation 不能兼作 revision，
否则正常更新会再次令别的应用排队事件失效。需要检查尚未持久化本地选择与新快照的竞态。

### R08 · P2 · 后台学习存储暂时失败后事件被丢弃且无可观测结果

证据：`learning_writer.cpp::run` 在 pop 后调用 updateProfile，失败时正常运行继续下一项，
仅 shutdown 时减少后续超时；满 128 项 enqueue 返回 false，`service.cpp` 未处理这个返回值。
磁盘暂时锁住、重命名失败或命名锁超时会让已确认的学习记录不可恢复。

输入不能被存储失败阻塞，这个方向正确。需改为后台有界重试、退避、失败统计和明确卸载上限，
保证只在真正成功后移除或明确丢弃事件；重试不能重复学习、复活清空数据或无限等待卸载。
当前缺少 worker 错误注入/恢复回归，不能把保存失败保留旧字节的测试当作事件恢复已通过。

### R09 · P2 · 自定义词库失败重载的 stamp 被当作已加载

证据：`service.cpp::acquireDictionary` 保留旧快照后仍无条件写 dictionaryCustom/dictionaryStamp。
一次临时访问失败后，相同 stamp 的后续 acquire 不再尝试，直到文件 metadata 再次变化。

只在成功接纳新快照后更新成功 stamp；失败需可重试、带退避且保留旧词库。
测试应锁住临时词库、触发重载、释放锁而不再改内容/时间，确认下一次成功得到新词库。
目前有静态路径证据，尚未完成生产 loader 的故障注入。

### R10 · P2 · fixture 的配置通知没有完全隔离（本批追加修复）

审查时发现，即使学习清空代际已经隔离，临时 preferences 保存和学习清空仍会发布生产配置通知。
它不改个人文件，仍可能导致打开应用重新读快照或退出闲置联想，造成测试干扰。
修复：所有包含配置写入/消费代码的测试 target 都定义隔离通知宏，以 PID 建立测试配置通道；
默认 watcher 和 publisher 共用解析函数，显式传入的跨进程测试通道及文件检测仍保留。
生产 DLL/设置程序继续使用原生产通道，测试宏不进入交付二进制。
原生 live 回归检查测试发布名称与生产名称不同且含 PID，再检查实际发布代际和既有消费者。
不能仅把 notifyConfiguration 全局删除，也不能把“个人数据字节未变”表述为“对会话完全无影响”。

## 评测与工程不足

### R11 · P2 · 质量与长尾性能缺少独立、持续的评测门槛

现有案例和手工语言边界可以防住已知错误，但不能估计真实中文输入中的错误候选率。
缺少训练/测试分离的整词、字词两线、长句、错漏键、缩写与前缀 gold corpus。
先记录来源/许可与标注协议，再评测 Top-1、Top-k、错误组合率、选词按键、词语复用/缓存命中，
分别统计准确输入和纠错输入，避免只测 zhang 或截图个例。
preview17 全规则混合长拼音核心 P99 约 12 ms，需要剖析与预算约束；不得用完整缩写最后一键
约 2 µs 掩盖整个输入序列的耗时。新模型和缓存变化必须经过同语料对比。

### R12 · P2 · 导入规范化、多词库合并峰值和同字数多解析

64 MiB 文件上限不等于合并的内存上限，多库串行重建会放大 CPU/峰值；缺少最大 64 库压力测量。
未分隔读音如 `xiangang` 既可能有不同字数切分，也可能有多个同字数切分；仅凭文字字数不能确定
`xi'an'gang` 或 `xi'ang'ang`。需要规范化导入保留可证明的分隔，或设计有界且有召回标记的多解析索引，
不能再次引入指数枚举/无界索引或静默裁掉词条。先实测再确定布局与预算。

### R13 · P3 · 发行版本存在多个手工来源

package REVISION、kVersion、UI 文本和 CI 安装包路径分别维护，当前 preview18 已同步。
后续用一个受审版本源生成 UI/packager/CI 元数据并检查未来版本 fixture；不要改写历史交付版本。

### R14 · P2 · 支持范围仍缺少实际宿主和设备证据

模拟 TSF、DPI fixture 和隔离安装 runner 都有价值，但不能替代 WinUI/浏览器/办公软件、
物理混合 DPI、远程桌面、不同键盘布局、长按、异常失焦及密码字段的实机矩阵。
Linux 桌面、Android、ARM64/x86 和双拼沿用路线图的未完成状态。本批不扩大支持承诺。
