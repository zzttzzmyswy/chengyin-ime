# 性能预算与复现

## 初始预算（目标，不是已达成声明）

在真实发布词库、发布构建和代表性长短输入回放上分别验收。具体硬件在 M2 前固定，桌面至少一台中端 x86_64，移动端至少一台中端 arm64。

| 指标 | 桌面目标 | Android 目标 | 口径 |
| --- | --- | --- | --- |
| 单按键核心计算 P99 | ≤0.5 ms | ≤1 ms | 包含规范化、解码、排序；不含 UI |
| 按键到候选可见 P95 / P99 | ≤8 / 16 ms | ≤16 / 32 ms | 含框架、IPC、UI 和渲染 |
| 核心热路径堆分配 | 稳态零分配 | 稳态零分配 | 词典/会话预热后；UI 单独计数 |
| 核心首用加载 | ≤50 ms | ≤100 ms | 生产二进制词典，冷/热缓存分别测 |
| 核心词典常驻内存 | 10 万词基线 ≤32 MiB | 同左 | 区分映射页、私有堆、RSS/PSS、加载峰值 |
| 单会话私有内存 | ≤64 KiB | ≤64 KiB | 不把只读词典重复计算到每个会话 |

整句模型、用户词库、候选翻页加入后重测。能耗以设备真实的 CPU 时间、唤醒次数与电量测量确定预算，不用桌面跑分替代。CI 共享主机先报告趋势；独立基准机重复出现 >10% 的 P99 回退再触发阻断，不能把噪声当回归。

## 复现命令

```sh
cargo test -p myswy-core --test allocations --locked
cargo bench -p myswy-core --bench latency --locked
```

当前 benchmark 无外部框架：场景采样次数分别标注，整串和查询先 200 次预热；逐键回放覆盖短词、长句、60 字节连续输入、首拼混输及连续上下文，使用 `Instant` 与 `black_box`，排序报告 P50/P95/P99/max。逐键回放不另设预热，包含每轮重置后的首键；连续上下文在一轮内只重置一次。计时器成本包含在结果中，没做校准扣除；云主机调度和频率会影响数据，纳秒尾数不表示相应精度。基准记录与界面测量分开。

## 需要补齐的基准

- 固定真实词库哈希、来源和版本；常用短词、长句、错误输入、稀有拼音、歧义切分、增量编辑、候选翻页。
- 与简单参考查词、现有成熟输入法在同词库/同任务上的对照；同时报告候选质量和性能。
- 磁盘冷启动/热启动、加载峰值、跨窗口共享词典、100 个会话、词库热替换。
- 按键链路分段打点：原生事件 → 核心 → UI 更新 → 实际呈现。采集时不得记录用户输入正文。
- 小词表上的优势不能作为生产词库性能结论；如引入模型，训练/加载/推理成本均需单列。
