## B 的实现安排

1. 独立 profile revision 与清空 generation。保存成功后发布 revision；磁盘 stamp 作通知失效时的后台补偿。
   不增加按键线程磁盘 I/O，不以正常 revision 丢弃队列。快照替换在 composition 结束后完成。
2. 避免用磁盘较旧快照覆盖本地未落盘选择。把 pending/in-flight 与 revision 顺序纳入设计；
   测试消费方在输入中、提交后、写队列未排空和另一个进程清空的交错。
3. 队列事件在失败后有限重试，限定总时长和次数，清空/导入代际每次重试重新核对。
   成功保存不能重复增加学习次数；队列满、永久损坏和卸载超时有不包含输入内容的计数。
4. 测试配置通道按运行实例隔离。需要真实跨进程生产 publisher 的单项测试时，也使用测试命名通道；
   所有文件均临时创建。回归不得依据个人历史排名。

## C 的实现安排

1. 抽取可注入路径的不可变词库 loader，复现临时文件访问失败；失败保留旧快照和未完成目标，
   成功才前移 stamp。后台重试使用退避，取消/卸载安全。
2. 测量 1/8/32/64 库、单次导入和启用切换的启动时间、峰值内存、分配与最终快照体积，
   然后确定一次合并/复用 immutable 字典的布局，不凭 64 MiB 文件限制承诺内存有界。
3. 处理未分隔同字数歧义时先保留来源音节证据。多解析若超预算必须有明确错误/标记或可重建机制，
   不允许静默漏词；既有二进制向后兼容和长规范读音测试保留。
4. 发行版本统一生成，历史文档与已交付包保留；未来版本 fixture 自动从当前版本导出。

## D / E 的验收安排

先用独立、可再分发或自造标注集分别测整词、单字、长句、同音歧义、11 组模糊音、
四类键盘失误、1–多字首拼、前缀选择与长期学习。样本数量和难度分布随结果报告，
不把用作开发修复的例子充作全部独立测试集。

微基准包含逐键、候选标记、编辑和翻页；只测共享核心，不混入 UI/IO。Windows 平台另测
从按键到宿主接受和候选绘制的延迟。优化前先确定业务预算，改善 P99 时同时检查首选/错误组合率。

实装批集中验证设置同步、输入/选择/原始 Space、Shift 符号、鼠标 caret、前缀取消、密码透传、
候选边缘定位和 DPI 转移。安装/升级/回滚/卸载由隔离 runner 先执行；个人桌面验证只作为独立证据。
遇到已确认的数据破坏或丢输入，新问题优先进入当前批次；性能和质量扩展不挤占修复。
